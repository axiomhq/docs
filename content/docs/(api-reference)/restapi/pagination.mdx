Use the [edge APL query endpoint](/restapi/endpoints/queryEdge) to retrieve events one page at a time. Axiom recommends timestamp-based pagination. Cursor-based pagination is in public preview and can distinguish events that share a timestamp.

<Prerequisites />

## Timestamp-based pagination

Sort by `_time` and use [`limit`](/apl/tabular-operators/limit-operator) to set the page size. For example, this request returns up to 100 events, newest first:

```bash
curl -X 'POST' 'https://AXIOM_DOMAIN/v1/query/_apl?format=tabular' \
  -H 'Authorization: Bearer API_TOKEN' \
  -H 'Content-Type: application/json' \
  -d '{
    "apl": "[\"DATASET_NAME\"] | sort by _time desc | limit 100",
    "startTime": "2026-11-01T00:00:00.000Z",
    "endTime": "2026-11-01T23:59:59.999Z"
  }'
```

To fetch the next page, use the last event’s `_time` as the new boundary:

| Sort order | Change for the next request |
| --- | --- |
| `sort by _time desc` | Set `endTime` to the last event’s timestamp. Keep `startTime` unchanged. |
| `sort by _time asc` | Set `startTime` to the last event’s timestamp. Keep `endTime` unchanged. |

The boundary is inclusive. Deduplicate repeated events in your client. Moving the boundary by a nanosecond can skip events that share that timestamp. If a full page shares a timestamp, use a cursor to continue through those events.

## Cursor-based pagination

Use a non-aggregated query with a single sort on `_time`, such as the query above. Keep the query, page size, and time range fixed across requests.

1. Send the first request without a cursor.
1. Read the boundary cursor from the response. For descending order, use `status.minCursor`. For ascending order, use `status.maxCursor`.
1. Send the same request with that value in the JSON body’s `cursor` field. By default the next page excludes the boundary event. Set `includeCursor` to `true` if you want to repeat it.
1. Continue until a page contains fewer events than the requested page size.
