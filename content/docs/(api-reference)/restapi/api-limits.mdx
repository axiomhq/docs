Axiom limits the number of calls a user (and their organization) can make over a certain period
of time to ensure fair usage and to maintain the quality of service for everyone.
Axiom systems closely monitor API usage and if a user exceeds any thresholds, Axiom
temporarily halts further processing of requests from that user (and/or organization).
This is to prevent any single user or app from overloading the system,
which could potentially impact other users' experience.

## Rate limits

Rate limits vary and are specified by the following headers in responses:

| Header                  | Description                                                                                                             |
| ----------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| `X-RateLimit-Scope`     | Indicates whether the limit counts against the organization or personal rate limit.                                     |
| `X-RateLimit-Limit`     | The maximum number of requests a user is permitted to make per minute.                                                  |
| `X-RateLimit-Remaining` | The number of requests remaining in the current rate limit window.                                                      |
| `X-RateLimit-Reset`     | The time at which the current rate limit window resets in UTC [epoch seconds](https://en.wikipedia.org/wiki/Unix_time). |

Possible values for `X-RateLimit-Scope`:

- `user`
- `organization`

When the request rate limit is exceeded, Axiom returns `429 Too Many Requests`:

```json
{
  "message": "rate limit exceeded"
}
```

## Query limits

Axiom enforces organization-level query budgets and optional per-token or per-user [query cost limits](/console/intelligence/query-cost-limits). The headers you receive depend on whether the query succeeds or is rejected with `429 Too Many Requests`.

### Headers on successful queries
Read `X-Axiom-Query-Cost-GBms` for the compute used by the query, in GB-milliseconds.

On successful edge APL queries (`POST /v1/query/_apl`), when the authenticating API token or user has configured hourly or daily query cost limits, Axiom returns per-window headers in **credits** reflecting post-query usage. Axiom only includes headers for windows that are configured on the token or user.

| Header                          | Description                                                                                                          |
| ------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| `X-QueryLimit-Hourly-Limit`     | Configured hourly query cost limit for the token or user, in credits.                                                |
| `X-QueryLimit-Hourly-Used`      | Credits used in the current hourly window after this query.                                                          |
| `X-QueryLimit-Hourly-Remaining` | Credits remaining in the current hourly window after this query.                                                     |
| `X-QueryLimit-Hourly-Reset`     | Time at which the hourly window resets, in UTC [epoch seconds](https://en.wikipedia.org/wiki/Unix_time).             |
| `X-QueryLimit-Daily-Limit`      | Configured daily query cost limit for the token or user, in credits.                                                 |
| `X-QueryLimit-Daily-Used`       | Credits used in the current daily window after this query.                                                           |
| `X-QueryLimit-Daily-Remaining`  | Credits remaining in the current daily window after this query.                                                      |
| `X-QueryLimit-Daily-Reset`      | Time at which the daily window resets, in UTC [epoch seconds](https://en.wikipedia.org/wiki/Unix_time).              |

Legacy core query endpoints on `api.axiom.co` return `X-QueryLimit-Limit`, `X-QueryLimit-Remaining`, and `X-QueryLimit-Reset` in Gigabyte Milliseconds (`GB*ms`).

### Exceeded query limits (`429 Too Many Requests`)

When an edge query exceeds an organization, token, or user query budget, Axiom returns `429 Too Many Requests` with headers describing the tripped budget:

| Header                     | Description                                                                                                    |
| -------------------------- | -------------------------------------------------------------------------------------------------------------- |
| `X-QueryLimit-Scope`       | Which budget was exceeded (`org`, `org-daily`, `token-hourly`, `token-daily`, `user-hourly`, or `user-daily`). |
| `X-QueryLimit-Limit`       | Configured budget for the tripped scope, in the unit reported by the response body (`credits` or `gbms`).      |
| `X-QueryLimit-Remaining`   | Remaining budget in the tripped scope.                                                                         |
| `X-QueryLimit-Reset`       | Time at which the tripped window resets, in UTC [epoch seconds](https://en.wikipedia.org/wiki/Unix_time).      |
| `X-QueryLimit-Retry-After` | Number of seconds to wait before retrying.                                                                     |

The `429` response body is a JSON object with the following fields:

```json
{
  "code": 429,
  "message": "query limit exceeded: token-hourly",
  "scope": "token-hourly",
  "unit": "credits",
  "limit": 100,
  "used": 120,
  "reset": "2026-11-01T12:00:00Z"
}
```

- `scope`: The budget that was exceeded: `org`, `org-daily`, `token-hourly`, `token-daily`, `user-hourly`, or `user-daily`.
- `unit`: The unit for `limit` and `used`. Token, user, and `org-daily` budgets use `credits`; the organization monthly cap (`org`) uses `gbms` (Gigabyte Milliseconds).
- `reset`: RFC 3339 UTC timestamp when the tripped window resets.

For batch queries (`POST /v1/query/batch`), per-item query-limit errors are delivered as Server-Sent Events (SSE) error events with status `429`, the same JSON body, and the `X-QueryLimit-*` headers.

## Ingest limits

| Header                    | Description                                                                                                             |
| ------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| `X-IngestLimit-Limit`     | The maximum bytes ingested a user is permitted to make per month.                                                       |
| `X-IngestLimit-Remaining` | The bytes ingested remaining in the current rate limit window.                                                          |
| `X-IngestLimit-Reset`     | The time at which the current rate limit window resets in UTC [epoch seconds](https://en.wikipedia.org/wiki/Unix_time). |

Alongside data volume limits, Axiom also monitors the rate of ingest requests.
If an organization consistently sends an excessive number of requests per second,
far exceeding normal usage patterns, Axiom reserves the right to suspend their ingest
to maintain system stability and ensure fair resource allocation for all users.
To prevent exceeding these rate limits, Axiom recommends using batching clients,
which can efficiently manage the number of requests by aggregating data before sending.
