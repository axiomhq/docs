Annotations mark events on charts in Query, dashboards, and monitors. Each annotation is associated with one or more datasets and marks a point in time or, with an end time, a time interval. The same annotation appears on supported charts that query those datasets. For example, use annotations to mark the time of the following:

- Deployments
- Server outages
- Incidents
- Feature flags

This adds context to the trends displayed in your charts and makes it easier to investigate issues in your app or system.

<Prerequisites />
- [Send data](/send-data/methods) to your Axiom dataset.
- To view annotations, use an account with permission to read annotations.
- For API requests and GitHub Actions, [create an API token](/reference/tokens) with the annotation permissions for the operations you use: create, read, update, or delete.

## Show and hide annotations in Query

Annotations appear for the queried dataset within the selected time range. To inspect an annotation, hold the pointer over its marker on the chart. Click or tap the marker to keep its details open. Press Escape to close pinned details.

### Event timeline

To display annotations on the event timeline:

1. Open **Query**, select a dataset, and run a query that returns events.
1. Select a time range that includes the annotation.
1. Open **Chart options** and enable **Show chart** and **Show annotations**.

### Aggregation charts

To choose annotation types on a time series or heatmap chart:

1. Run a query that produces a time series or heatmap for the dataset associated with the annotation.
1. Select a time range that includes the annotation.
1. Open **Chart options** and select **Annotations**.
1. Select the annotation types to display, or select **Show all annotations** or **Hide all annotations**.

If the results contain several charts, open the relevant chart’s submenu before selecting **Annotations**. Annotation controls are available for time series and percentile charts, and for a heatmap when it is the only aggregation chart. Scatter plots and categorical charts do not display annotations.

For more information, see [Query results](/query-data/query-results#configure-chart-options).

## Show and hide annotations on dashboards

To choose annotation types across a dashboard:

1. Open the dashboard and select a time range that includes the annotation.
1. In the dashboard toolbar, click **Annotations**.
1. Select the annotation types to display. Use **All annotations** to show or hide all listed types.

Use **Search annotations** to filter the type list. While a search is active, **All matches** changes only the matching types. Clear the search to manage all types.

To access the same controls while editing a time series or heatmap element, expand **Chart** in the settings panel and click **Manage** in **Annotations**. If the panel is hidden, click **Settings**. For more information, see [Configure dashboard elements](/dashboard-elements/configure#annotations).

The annotation’s datasets determine which charts display it. The annotation controls filter by type, such as `deploy`. Dashboard annotation choices affect the current view and are not saved as dashboard settings. Controls in an individual element’s chart settings use the same visibility choices across the dashboard.

## Show and hide annotations in monitors

Threshold and anomaly monitor charts display annotations for the monitor’s dataset and the chart’s time range. Use annotations to compare deployments and incidents with the data used to evaluate the monitor.

### Monitor detail pages

On desktop, the **Annotations** diamond icon sits to the right of the time range in **Recent activity**.

<Note>
On phones, open **Recent activity options** (`⋯`) to access **Time range** and **Annotations**. Each action opens a sheet.
</Note>

To choose annotation types on a monitor detail page:

1. Open **Monitors** and select a threshold or anomaly monitor.
1. In **Recent activity**, select a time range that includes the annotation.
1. Open **Annotations**.
1. Select the types to display. Use **All annotations** to show or hide all listed types.

Use **Search annotations** to filter the type list. While a search is active, **All matches** changes only matching types.

The type list follows the chart’s dataset and time range, including a zoomed range. The control appears after a supported chart loads and is disabled while the query runs. Visibility choices affect the current view and are not saved with the monitor.

### Show and hide annotations in monitor previews

To choose annotation types in a monitor preview:

1. Open a threshold or anomaly monitor in the monitor editor.
1. Select a preview time range that includes the annotation and run the query to produce a supported time series or heatmap chart.
1. In the settings panel, expand **Chart**. If the panel is hidden, click **Settings**.
1. In **Annotations**, click **Manage**.
1. Select the annotation types to display, or select **Show all annotations** or **Hide all annotations**.

Visibility choices affect the current view and are not saved with the monitor. Both detail and preview controls support time series and percentile results, or a heatmap when it is the only aggregation chart. Run the preview query and select a range with annotations to make **Manage** available.

For more information, see [Configure monitors](/monitor-data/configure-monitors).

## Display limits

Chart annotation requests cover at most 100 days. If the selected chart range is longer, Axiom loads annotations only for the latest 100 days of that range. To inspect older annotations, select a shorter range around the event.

The public Playground does not load organization annotations.

Annotation controls list the types found for the selected datasets and time range. If no annotations exist in that range, change the range or create an annotation for the dataset.

## Troubleshoot missing annotations

If an annotation does not appear, check the following:

- The annotation's `datasets` list includes the dataset used by the chart.
- The chart's time range includes the annotation's time or overlaps its time interval.
- The annotation’s type is visible in the annotation controls.
- The annotation’s point in time or time interval overlaps the latest 100 days of the selected chart range.
- For event queries, **Show chart** and **Show annotations** are enabled.
- Your user or API token has permission to read annotations.

## Create annotations

Create annotations in one of the following ways:

- [Use a GitHub Action](#create-annotations-with-github-actions)
- [Send a request to the Axiom API](#create-annotations-using-axiom-api)

The [Axiom Vercel integration](/apps/vercel) also creates annotations when deployments complete.

### Create annotations with GitHub Actions

Configure GitHub Actions using YAML syntax. For more information, see the [GitHub documentation](https://docs.github.com/en/actions/learn-github-actions/understanding-github-actions#create-an-example-workflow).

To create an annotation after a deployment, add the following step after the deployment step in your GitHub Actions workflow:

```yml
- name: Add annotation in Axiom when a deployment happens
  uses: axiomhq/annotation-action@v0.2.0
  with:
    axiomToken: ${{ secrets.API_TOKEN }}
    datasets: DATASET_NAME
    type: "production-release"
    title: "Production deployment"
    description: "Commit ${{ github.event.head_commit.message }}"
```

<ReplaceDatasetToken />
</Info>

The action uses the current time and links to the workflow run by default. Optional: Set `time` for a historical event, `endTime` for an interval, or `url` for a different link. For the available inputs, see the [annotation action](https://github.com/axiomhq/annotation-action).

### Create annotations using Axiom API

To create an annotation using the Axiom API, use the following API request:

```bash
curl -X 'POST' 'https://api.axiom.co/v2/annotations' \
  -H 'Authorization: Bearer API_TOKEN' \
  -H 'Content-Type: application/json' \
  -d '{
    "time": "2024-03-18T08:39:28.382Z",
    "type": "deploy",
    "datasets": ["DATASET_NAME"],
    "title": "Production deployment",
    "description": "Deploy new feature to the sales form",
    "url": "https://example.com"
  }'
```

<Info>
<ReplaceDatasetToken />
</Info>

Replace `time` with the event timestamp, or omit it to use the time of the API request. A start time in the future is rejected. Customize the title, description, and URL. For more information on the allowed fields, see [Annotation object](#annotation-object).

**Example response**

```json
{
  "datasets": ["my-dataset"],
  "description": "Deploy new feature to the sales form",
  "id": "ann_123",
  "time": "2024-03-18T08:39:28.382Z",
  "title": "Production deployment",
  "type": "deploy",
  "url": "https://example.com"
}
```

The API response contains an `id` field. Use this annotation ID to change or delete the annotation.

## Get information about annotations

To list annotations in your organization, use the following API request:

```bash
curl -X 'GET' 'https://api.axiom.co/v2/annotations' \
  -H 'Authorization: Bearer API_TOKEN'
```

<Info>
<ReplaceToken />
</Info>

Without filters, this endpoint returns all annotations in the organization. Use the following parameters to filter the results:

- `start` is an RFC 3339 timestamp that specifies the beginning of the time interval.
- `end` is an RFC 3339 timestamp that specifies the end of the time interval.
- `datasets` is the list of datasets whose annotations you want to get information about. Separate datasets by commas, for example `datasets=my-dataset1,my-dataset2`.

Set both `start` and `end`, or omit both. The end is at or after the start, and the range is at most 100 days. Results include annotations whose time interval overlaps the requested range.

The following example lists annotations for `my-dataset` between March 16 and 19, 2024:

```bash
curl -X 'GET' 'https://api.axiom.co/v2/annotations?start=2024-03-16T00:00:00.000Z&end=2024-03-19T23:59:59.999Z&datasets=my-dataset' \
  -H 'Authorization: Bearer API_TOKEN'
```

**Example response**

```json
[
  {
    "datasets": ["my-dataset"],
    "description": "Deploy new feature to the navigation component",
    "id": "ann_234",
    "time": "2024-03-17T01:15:45.232Z",
    "title": "Production deployment",
    "type": "deploy",
    "url": "https://example.com"
  },
  {
    "datasets": ["my-dataset"],
    "description": "Deploy new feature to the sales form",
    "id": "ann_123",
    "time": "2024-03-18T08:39:28.382Z",
    "title": "Production deployment",
    "type": "deploy",
    "url": "https://example.com"
  }
]
```

The API response contains an `id` field. Use this annotation ID to change or delete the annotation. For more information on the other fields, see [Annotation object](#annotation-object).


## Change annotations

To change an existing annotation, use the following API request:

```bash
curl -X 'PUT' 'https://api.axiom.co/v2/annotations/ANNOTATION_ID' \
  -H 'Authorization: Bearer API_TOKEN' \
  -H 'Content-Type: application/json' \
  -d '{
    "endTime": "2024-03-18T08:49:28.382Z"
  }'
```

<Info>
Replace `ANNOTATION_ID` with the ID of the annotation. For more information about how to determine the annotation ID, see [Get information about annotations](#get-information-about-annotations).
<ReplaceToken />
In the payload, specify the properties to change. Omitted fields keep their current values. Empty strings and an empty `datasets` list also keep their current values; they do not clear a field. The example above adds an `endTime` field to the annotation created above. For more information on the allowed fields, see [Annotation object](#annotation-object).
</Info>

**Example response**

```json
{
  "datasets": ["my-dataset"],
  "description": "Deploy new feature to the sales form",
  "id": "ann_123",
  "time": "2024-03-18T08:39:28.382Z",
  "title": "Production deployment",
  "type": "deploy",
  "url": "https://example.com",
  "endTime": "2024-03-18T08:49:28.382Z"
}
```

## Annotation object

Annotations have the following fields:

| Field | Description |
| --- | --- |
| `datasets` | Required when creating an annotation. One or more existing dataset names. |
| `id` | Unique annotation ID returned by Axiom. Use it to retrieve, update, or delete the annotation. |
| `time` | Event start time in RFC 3339 format. If omitted on creation, Axiom uses the request time. Future start times are rejected. |
| `endTime` | Optional end time in RFC 3339 format, at or after `time`. Omit it for a point in time. If it equals `time` on creation, Axiom stores a point in time. |
| `type` | Required when creating an annotation. A name of at most 256 characters using lowercase letters, numbers, and hyphens, such as `production-deployment`. Used to group annotations in display controls. |
| `title` | Optional summary. Axiom truncates values longer than 256 Unicode characters and ends the result with an ellipsis. |
| `description` | Optional explanation of the event. Axiom truncates values longer than 512 Unicode characters and ends the result with an ellipsis. |
| `url` | Optional link to the deployment, incident, or other related resource. Maximum length: 512 characters. |

For the full request and response schemas, see [Create annotation](/restapi/endpoints/createAnnotation), [List annotations](/restapi/endpoints/getAnnotations), and [Update annotation](/restapi/endpoints/updateAnnotation).

## Example use case

The example below demonstrates how annotations help you troubleshoot issues in your app or system. Your monitor alerts you about rising form submission errors. You explore this trend and when it started. Right before form submission errors started rising, you see an annotation about a deployment of a new feature to the form. You make the hypothesis that the deployment is the reason for the error and decide to investigate the code changes it introduced.

### Create annotation

Use the following API request to create an annotation:

```bash
curl -X 'POST' 'https://api.axiom.co/v2/annotations' \
  -H 'Authorization: Bearer API_TOKEN' \
  -H 'Content-Type: application/json' \
  -d '{
    "time": "2024-03-18T08:39:28.382Z",
    "type": "deploy",
    "datasets": ["my-dataset"],
    "title": "Production deployment",
    "description": "Deploy new feature to the sales form",
    "url": "https://example.com"
```
