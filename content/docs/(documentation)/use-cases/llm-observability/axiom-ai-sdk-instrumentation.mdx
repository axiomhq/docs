This page explains how to send telemetry from a TypeScript generative AI app built with [Vercel AI SDK](https://ai-sdk.dev/docs) to Axiom.

How you instrument your app depends on your version of Vercel AI SDK:

| Vercel AI SDK version | Instrumentation | Axiom package required |
|:----------------------|:----------------|:-----------------------|
| 7 | [Built-in AI SDK telemetry](#instrument-ai-sdk-7) | No |
| 4, 5, and 6 | [Axiom AI SDK wrappers](#instrument-ai-sdk-4-5-and-6) | Yes, `axiom` |

Vercel AI SDK 7 emits OpenTelemetry spans with the GenAI semantic conventions natively, so you only need to export them to Axiom. Earlier versions need Axiom AI SDK to create these spans.

Alternatively, [instrument your app manually](/use-cases/llm-observability/manual-instrumentation). For more information on instrumentation approaches, see [LLM observability](/use-cases/llm-observability).

## Prerequisites

1. Install the OpenTelemetry packages:

    ```sh
    npm i @opentelemetry/api @opentelemetry/sdk-trace-node @opentelemetry/exporter-trace-otlp-http @opentelemetry/resources @opentelemetry/semantic-conventions
    ```

1. Set the `AXIOM_TOKEN` and `AXIOM_DATASET` environment variables using an [API token](/reference/tokens) with ingest permission and the name of the dataset where you send telemetry.

## Export traces to Axiom

Both instrumentation methods write spans to the global OpenTelemetry API. Register a `NodeTracerProvider` with an `OTLPTraceExporter` that sends spans to Axiom. Replace `AXIOM_DOMAIN` with the [domain for your dataset](/send-data/opentelemetry).

```ts src/instrumentation.node.ts
import { OTLPTraceExporter } from '@opentelemetry/exporter-trace-otlp-http';
import { resourceFromAttributes } from '@opentelemetry/resources';
import { BatchSpanProcessor, NodeTracerProvider } from '@opentelemetry/sdk-trace-node';
import { ATTR_SERVICE_NAME } from '@opentelemetry/semantic-conventions';

const exporter = new OTLPTraceExporter({
  url: 'https://AXIOM_DOMAIN/v1/traces',
  headers: {
    Authorization: `Bearer ${process.env.AXIOM_TOKEN}`,
    'X-Axiom-Dataset': process.env.AXIOM_DATASET!,
  },
});

const provider = new NodeTracerProvider({
  resource: resourceFromAttributes({
    [ATTR_SERVICE_NAME]: 'my-ai-app',
  }),
  spanProcessors: [new BatchSpanProcessor(exporter)],
});

provider.register();
```

Load this file once at application startup, before your app makes any LLM calls:

- In a Node.js app, import it at the top of your entry file: `import './instrumentation.node';`
- In a Next.js app, import it from the `register` function in `src/instrumentation.ts`. Next.js also loads this file in the Edge runtime, so import the Node.js setup only in the Node.js runtime:

    ```ts src/instrumentation.ts
    export async function register() {
      if (process.env.NEXT_RUNTIME === 'nodejs') {
        await import('./instrumentation.node');
      }
    }
    ```

## Instrument AI SDK 7

Vercel AI SDK 7 creates spans for model calls, tool executions, and agent steps through its OpenTelemetry integration. You don’t need Axiom AI SDK.

1. Install Vercel AI SDK, a provider, and the AI SDK OpenTelemetry integration:

    ```sh
    npm i ai @ai-sdk/openai @ai-sdk/otel
    ```

1. Register the integration at the end of `src/instrumentation.node.ts`, after `provider.register()`:

    ```ts src/instrumentation.node.ts
    import { OpenTelemetry } from '@ai-sdk/otel';
    import { registerTelemetry } from 'ai';

    // ...exporter and provider setup from the previous section

    registerTelemetry(new OpenTelemetry());
    ```

After you register the integration, AI SDK calls emit telemetry by default. You don’t need to wrap models or tools. To group spans by feature, set `telemetry.functionId`. AI SDK records it as `gen_ai.agent.name`.

```ts src/app/page.tsx
import { openai } from '@ai-sdk/openai';
import { generateText, stepCountIs, tool } from 'ai';
import { z } from 'zod';

export default async function Page() {
  const { text } = await generateText({
    model: openai('gpt-4o'),
    telemetry: { functionId: 'get_directions' },
    stopWhen: stepCountIs(5),
    messages: [{ role: 'user', content: 'How do I get from Paris to Berlin?' }],
    tools: {
      findDirections: tool({
        description: 'Find directions to a location',
        inputSchema: z.object({ from: z.string(), to: z.string() }),
        execute: async ({ from, to }) => ({
          directions: `To get from ${from} to ${to}, use a teleporter.`,
        }),
      }),
    },
  });

  return <p>{text}</p>;
}
```

AI SDK records prompts, responses, tool arguments, and tool results by default. To exclude them from a call, set `telemetry: { recordInputs: false, recordOutputs: false }`. To turn off telemetry for a call, set `telemetry: { isEnabled: false }`. For more information, see the [AI SDK telemetry documentation](https://ai-sdk.dev/docs/ai-sdk-core/telemetry).

## Instrument AI SDK 4, 5, and 6

For Vercel AI SDK 4, 5, and 6, use Axiom AI SDK to wrap your models and tools.

<Info>
Axiom AI SDK is an open-source project and welcomes your contributions. For more information, see the [GitHub repository](https://github.com/axiomhq/ai).
</Info>

<Warning>
Axiom AI SDK doesn’t instrument Vercel AI SDK 7 models. If you pass one to `wrapAISDKModel` or `axiomAIMiddleware`, Axiom AI SDK logs a warning and sends no spans. Use the [built-in AI SDK 7 telemetry](#instrument-ai-sdk-7) instead.
</Warning>

The examples in this section use Vercel AI SDK 6. Version 5 uses the same code. For Vercel AI SDK 4, replace `inputSchema` with `parameters` in tool definitions, and replace `stopWhen: stepCountIs(5)` with `maxSteps: 5`.

### Initialize Axiom AI SDK

1. Install Axiom AI SDK and Zod:

    ```sh
    npm i axiom zod
    ```

1. At the end of `src/instrumentation.node.ts`, after `provider.register()`, create a tracer and pass it to `initAxiomAI`:

    ```ts src/instrumentation.node.ts
    import { trace } from '@opentelemetry/api';
    import { initAxiomAI, RedactionPolicy } from 'axiom/ai';

    // ...exporter and provider setup from the previous section

    const tracer = trace.getTracer('my-ai-app');

    initAxiomAI({ tracer, redactionPolicy: RedactionPolicy.AxiomDefault });
    ```

Axiom AI SDK doesn’t read `AXIOM_TOKEN` or `AXIOM_DATASET` directly. The exporter you registered sends its spans to Axiom. For redaction options, see [Redaction policies](/use-cases/llm-observability/redaction-policies).

#### Use `axiomAIMiddleware` with `wrapLanguageModel`

If you already compose middleware with the Vercel AI SDK’s `wrapLanguageModel`, pass `axiomAIMiddleware({ model })` instead of calling `wrapAISDKModel`:

```ts src/shared/openai.ts
import { wrapLanguageModel } from 'ai';
import { createOpenAI } from '@ai-sdk/openai';
import { axiomAIMiddleware } from 'axiom/ai';

const openaiProvider = createOpenAI({
  apiKey: process.env.OPENAI_API_KEY,
});

const baseModel = openaiProvider('gpt-4o');

export const gpt4o = wrapLanguageModel({
  model: baseModel,
  middleware: [axiomAIMiddleware({ model: baseModel })],
});
```

The rest of this section explains how to work with OpenAI. The process is similar for other LLMs.

### Add context

The `withSpan` function allows you to add crucial business context to your traces. It creates a parent span around your LLM call and attaches metadata about the `capability` and `step` that you execute.

```ts /src/app/page.tsx
import { withSpan } from 'axiom/ai';
import { generateText } from 'ai';
import { gpt4o } from '@/shared/openai';

export default async function Page() {
  const userId = 123;

  // Use withSpan to define the capability and step
  const res = await withSpan({ capability: 'get_capital', step: 'generate_answer' }, (span) => {
    // You have access to the OTel span to add custom attributes
    span.setAttribute('user_id', userId);

    return generateText({
      model: gpt4o, // Use the wrapped model
      messages: [
        {
          role: 'user',
          content: 'What is the capital of Spain?',
        },
      ],
    });
  });

  return <p>{res.text}</p>;
}
```

### Instrument tool calls

For many AI capabilities, the LLM call is only part of the story. If your capability uses tools to interact with external data or services, observing the performance and outcome of those tools is critical. Axiom AI SDK provides the `wrapTool` and `wrapTools` functions to automatically instrument your Vercel AI SDK tool definitions.

The `wrapTool` helper takes your tool’s name and its definition and returns an instrumented version. This wrapper creates a dedicated child span for every tool execution, capturing its arguments, output, and any errors.

By default, `generateText` stops after the first step. To let the model answer after it calls a tool, set `stopWhen`.

```ts /src/app/generate-text/page.tsx
import { generateText, stepCountIs, tool } from 'ai';
import { z } from 'zod';
import { wrapTool } from 'axiom/ai';
import { gpt4o } from '@/shared/openai';

// In your generateText call, provide wrapped tools
const { text, toolResults } = await generateText({
  model: gpt4o,
  stopWhen: stepCountIs(5),
  messages: [
    { role: 'system', content: 'You are a helpful assistant.' },
    { role: 'user', content: 'How do I get from Paris to Berlin?' },
  ],
  tools: {
    // Wrap each tool with its name
    findDirections: wrapTool(
      'findDirections', // The name of the tool
      tool({
        description: 'Find directions to a location',
        inputSchema: z.object({
          from: z.string(),
          to: z.string(),
        }),
        execute: async (params) => {
          // Your tool logic here...
          return { directions: `To get from ${params.from} to ${params.to}, use a teleporter.` };
        },
      })
    )
  }
});
```

To wrap several tools at once, pass a tool map to `wrapTools`:

```ts src/app/generate-text/page.tsx
import { generateText, stepCountIs, tool } from 'ai';
import { wrapTools } from 'axiom/ai';
import { z } from 'zod';
import { gpt4o } from '@/shared/openai';

const tools = wrapTools({
  findDirections: tool({
    description: 'Find directions to a location',
    inputSchema: z.object({ from: z.string(), to: z.string() }),
    execute: async ({ from, to }) => ({
      directions: `To get from ${from} to ${to}, use a teleporter.`,
    }),
  }),
});

const { text } = await generateText({
  model: gpt4o,
  stopWhen: stepCountIs(5),
  messages: [{ role: 'user', content: 'How do I get from Paris to Berlin?' }],
  tools,
});
```

### Complete example

Example of how all three instrumentation functions work together in a single, real-world example:

```ts /src/app/page.tsx expandable
import { withSpan, wrapAISDKModel, wrapTool } from 'axiom/ai';
import { generateText, stepCountIs, tool } from 'ai';
import { createOpenAI } from '@ai-sdk/openai';
import { z } from 'zod';

// 1. Create and wrap the AI model client
const openaiProvider = createOpenAI({
  apiKey: process.env.OPENAI_API_KEY,
});
const gpt4o = wrapAISDKModel(openaiProvider('gpt-4o'));

// 2. Define and wrap your tool(s)
const findDirectionsTool = wrapTool(
  'findDirections', // The tool name must be passed to the wrapper
  tool({
    description: 'Find directions to a location',
    inputSchema: z.object({ from: z.string(), to: z.string() }),
    execute: async ({ from, to }) => ({
      directions: `To get from ${from} to ${to}, use a teleporter.`,
    }),
  })
);

// 3. In your application logic, use `withSpan` to add context
//    and call the AI model with your wrapped tools.
export default async function Page() {
  const userId = 123;

  const { text } = await withSpan({ capability: 'get_directions', step: 'generate_ai_response' }, async (span) => {
    // You have access to the OTel span to add custom attributes
    span.setAttribute('user_id', userId);

    return generateText({
      model: gpt4o, // Use the wrapped model
      stopWhen: stepCountIs(5),
      messages: [
        { role: 'system', content: 'You are a helpful assistant.' },
        { role: 'user', content: 'How do I get from Paris to Berlin?' },
      ],
      tools: {
        findDirections: findDirectionsTool, // Use the wrapped tool
      },
    });
  });

  return <p>{text}</p>;
}
```

This demonstrates the three key steps to rich observability:

1. **`wrapAISDKModel`**: Automatically captures telemetry for the LLM provider call
1. **`wrapTool`**: Instruments the tool execution with detailed spans
1. **`withSpan`**: Creates a parent span that ties everything together under a business capability
