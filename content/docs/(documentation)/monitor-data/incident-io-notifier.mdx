To create an incident.io notifier, follow these steps:

1. In incident.io, create an HTTP alert source and copy its alert events URL and token. For more information, see the [incident.io documentation](https://docs.incident.io/alerts/custom-http-sources).
1. In Axiom, click **Notifiers** in the sidebar.
1. Click **New notifier**.
1. Name your notifier.
1. Click **incident.io**.
1. In **Alert source ID**, enter the last segment of the alert events URL.
1. In **Token**, enter the token of the HTTP alert source.
1. Click **Create**.

With **Notify by group**, each group gets its own alert, and the alert’s description covers only that group. If you turn off **Notify on resolve**, alerts stay open until you close them in incident.io. For more information, see [Notification settings](/monitor-data/configure-monitors#notification-settings).

## Alert metadata

Alerts that Axiom sends to incident.io include the following metadata fields:

- `monitor_id` and `monitor_name`: The monitor’s ID and name. Included on every alert.
- `description`: The monitor’s description, when the monitor has one. Included on every alert from that monitor.
- `value`: The measured value, for threshold and anomaly monitors only. Omitted for no-data alerts, for match and new values monitors, and when one alert covers several groups.
- `group`: With **Notify by group**, the group’s values as one readable string, such as `warn & home-energy`.
- `groups`: With **Notify by group**, a map of each group key to its value, such as `{"level": "warn", "team": "home-energy"}`. Missing values are empty strings.
