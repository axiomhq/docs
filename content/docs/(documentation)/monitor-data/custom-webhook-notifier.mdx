Use a custom webhook notifier to connect your monitors to internal or external services. The webhook URL receives a POST request with a content type of `application/json` together with any other headers you specify.

To create a custom webhook notifier, follow these steps:

1. In Axiom, click **Notifiers** in the sidebar.
1. Click **New notifier** on the top right.
1. Name your notifier.
1. Click **Custom webhook**.
1. In **Webhook URL**, enter the URL where you want to send the POST request. The URL must use HTTPS. Axiom rejects `http://` URLs when you save or test the notifier.
1. Optional: To customize the content of your webhook, use the [Go template syntax](https://pkg.go.dev/text/template) to interact with these variables:
    - `.Action` has value `Open` when the notification corresponds to a match monitor matching, a new values monitor finding a new value, or a threshold or anomaly monitor triggering, and has value `Closed` when a threshold or anomaly monitor resolves.
    - `.MonitorID` is the unique identifier for the monitor associated with the notification.
    - `.MonitorURL` is a link to the monitor in Axiom.
    - `.Query` is the APL or MPL query of the monitor associated with the notification.
    - `.QueryURL` is a link that opens the query of the monitor in Axiom over the time range of the notification. It’s empty if Axiom can’t build the link.
    - `.Name` is the name of the monitor.
    - `.MonitorType` is the type of the monitor.
    - `.Labels` is an array of labels associated with the notification.
    - `.Threshold` and `.Operator` are the monitor’s configured threshold and comparison operator.
    - `.Range` and `.Interval` are the query range and run interval in minutes.
    - `.ID` is the notification event ID.
    - `.UUID` is a UUID generated for the webhook message.
    - `.Body` contains the notification message. For match monitors, it contains `Event Matched` and a rate-limit note when applicable. For new values monitors, it contains the accompanying text or `New Value` if none was provided. For threshold or anomaly monitors, it describes the value that triggered or resolved the alert. Use `.MatchedEvent` to read the matching event or new value row.
    - `.Description` is the description of the monitor associated with the notification.
    - `.QueryEndTime` is the end time applied in the monitor query that gave rise to the notification.
    - `.QueryStartTime` is the start time applied in the monitor query that gave rise to the notification.
    - `.Timestamp` is the time the notification was generated.
    - `.Title` is the notification title.
    - `.Value` is the value that gave rise to the monitor triggering or resolving. It applies to threshold and anomaly monitors. When a threshold or anomaly monitor resolves because its query stops returning data for a series (for example, a grouped series that goes idle or drops out), there’s no current value to report and `.Value` is `0`.
    - `.MatchedEvent` is a JSON object. It’s only applicable if the notification corresponds to a match monitor or a new values monitor. For a match monitor, it’s the event that matched the criteria of the monitor. For a new values monitor, it’s one row of the query results that holds the new value.
    - `.GroupKeys` and `.GroupValues` are JSON arrays that contain the keys and the values returned by the group-by attributes of your query. They’re only applicable if the APL query of the monitor groups by a non-time field.
    You can fully customize the content of the webhook to match the requirements of your environment.
1. Optional: In **Webhook headers**, add headers to the POST request. For sensitive values such as authentication tokens, use **Webhook secret headers**. Axiom encrypts these values and hides them when you edit the notifier.
1. Click **Create**.

## Template functions

Use `jsonObject` to include `.MatchedEvent` as a JSON object, and `jsonArray` to include arrays such as `.GroupKeys` or `.Labels`.

Use `jsonString` to quote a string as JSON, for example `"name": {{jsonString .Name}}`. To include the matched event as a string, use `"event": "{{escapedJSON .MatchedEvent}}"`.

## Examples

The example below is the default template for a custom webhook notification:

```json
{
  "action": "{{.Action}}",
  "event": {
    "monitorID": "{{.MonitorID}}",
    "body": "{{.Body}}",
    "description": "{{.Description}}",
    "queryEndTime": "{{.QueryEndTime}}",
    "queryStartTime": "{{.QueryStartTime}}",
    "timestamp": "{{.Timestamp}}",
    "title": "{{.Title}}",
    "value": {{.Value}},
    "matchedEvent": {{jsonObject .MatchedEvent}},
    "groupKeys": {{jsonArray .GroupKeys}},
    "groupValues": {{jsonArray .GroupValues}}
  }
}
```

Using the template above, the body of a POST request sent to the webhook URL for a threshold monitor triggering:

```json
{
  "action": "Open",
  "event": {
    "monitorID": "CabI3w142069etTgd0",
    "body": "Current value of 57347 is above or equal to the threshold value of 0",
    "description": "",
    "queryEndTime": "2024-06-28 14:55:57.631364493 +0000 UTC",
    "queryStartTime": "2024-06-28 14:45:57.631364493 +0000 UTC",
    "timestamp": "2024-06-28 14:55:57 +0000 UTC",
    "title": "Axiom Monitor Test Triggered",
    "value": 57347,
    "matchedEvent": null,
    "groupKeys": null,
    "groupValues": null
  }
}
```

The example template below formats the webhook message to match the [expectations of incident.io](https://api-docs.incident.io/tag/Alert-Events-V2/) using the monitor ID as the `deduplication_key`. To use the native integration, see [incident.io notifier](/monitor-data/incident-io-notifier).

```json
{
  "title": "{{.Title}}",
  "description": "{{.Body}}",
  "deduplication_key": "{{.MonitorID}}",
  "status": "{{ if eq .Action "Open" }}firing{{ else }}resolved{{ end }}",
  "metadata": {
    "description": "{{.Description}}",
    "value": {{.Value}}
  },
  "source_url": "{{.MonitorURL}}"
}
```

The example template below sends the query and the links that your own automation needs to start an investigation when a monitor alerts:

```json
{
  "title": "{{.Title}}",
  "action": "{{.Action}}",
  "query": "{{.Query}}",
  "queryURL": "{{.QueryURL}}",
  "monitorURL": "{{.MonitorURL}}"
}
```
