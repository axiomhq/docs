Match monitors allow you to continuously filter your log data and send you matching events. Axiom sends a notification for each matching event. By default, the notification message contains the entire matching event in JSON format. When you define your match monitor using APL, you can control which event attributes to include in the notification message.

Axiom recommends using match monitors for alerting purposes only. A match monitor runs every minute and reports up to nine matching events per run. For notification rate limits, see [Notification limits](/monitor-data/notifiers-overview#notification-limits). A notification can usually include events up to 0.1 MB but the maximum size can be smaller depending on the type of the notifier.

## Create match monitor

To create a match monitor, follow these steps:

1. Click **Monitors** in the sidebar, and then click **New monitor**.
1. In **Monitor type**, select **Match**.
1. Name your monitor and add a description.
1. Click **Add notifier**, and then select the notifiers that define how you want to receive notifications for this monitor. For more information, see [Notifiers](#notifiers).
1. To define your query, use one of the following options:
    - Click **Builder**, select your filters, and then click **Run** to preview matching events. To preview events from a specific period, select the time range.
    - Click **Editor** and write an APL query using `where` to filter for events. Click **Run** to preview the results. To transform matching events before sending them to you, use the `extend` and the `project` operators. Don’t use aggregations in your query. For more information, see [Introduction to APL](/apl/introduction).
1. Optional: Configure an [evaluation delay](/monitor-data/configure-monitors#data-that-arrives-late) to account for late events.
1. When the preview displays the events that you want to match, click **Save**. You can’t create a match monitor if more than 500 events match your query within the past 24 hours.

You have created a match monitor, and Axiom alerts you about every event that matches the filters you set. Each notification contains the event details as shown in the preview.

<Info>
If you define your query using APL, you can use the following limited set of tabular operators:

- [extend](/apl/tabular-operators/extend-operator)
- [extend-valid](/apl/tabular-operators/extend-valid-operator)
- [lookup](/apl/tabular-operators/lookup-operator)
- [parse](/apl/tabular-operators/parse-operator)
- [parse-kv](/apl/tabular-operators/parse-kv)
- [project](/apl/tabular-operators/project-operator)
- [project-away](/apl/tabular-operators/project-away-operator)
- [project-keep](/apl/tabular-operators/project-keep-operator)
- [project-rename](/apl/tabular-operators/project-rename)
- [project-reorder](/apl/tabular-operators/project-reorder-operator)
- [redact](/apl/tabular-operators/redact-operator)
- [union](/apl/tabular-operators/union-operator)
- [where](/apl/tabular-operators/where-operator)

Use `lookup` to enrich matching events with a table you define in the query using `datatable`, and use `redact` to mask sensitive values before Axiom sends them in the notification.

This restriction only applies to tabular operators.
</Info>
