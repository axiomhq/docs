Dashboards provide a single view into your data. They visualize collections of queries across multiple datasets in one place. Dashboards are easy to share, benefit from collaboration, and bring separate datasets together in a single view.

## Dashboards

In the sidebar, click **Dashboards** to view the dashboards you have access to. Dashboards are grouped into **Integration**, **Organization**, and **Private** sections. Use the filter bar at the top of the list to filter by **Dashboard type**, **Group**, **Edge**, or search by name.

- The **Integration** section lists prebuilt dashboards. Axiom automatically builds these dashboards as part of the [apps that enrich your Axiom experience](/apps/introduction). Integration dashboards are read-only and you can’t edit them. To create a copy of an integration dashboard that you can edit, [fork the original dashboard](#fork-dashboards).
- The **Organization** and **Private** sections list the shared and private dashboards you can access.

To open a dashboard, click a dashboard in the list.

### Integration dashboards

To view integration dashboards, open **Dashboards** and expand **Integration**. Axiom automatically discovers supported data and creates read-only dashboards for datasets you can access.

- For event datasets, Axiom creates a dashboard when all required fields are present in the dataset schema.
- For metrics datasets, Axiom creates a dashboard when the dataset received all required metrics in the last 24 hours.

Automatically discovered dashboards include the dataset name in their title, for example `Kubernetes Stats (DATASET_NAME)`. A single dataset can match more than one integration dashboard.

| Dashboard | Dataset type | Required fields or metrics | What it shows |
| :--- | :--- | :--- | :--- |
| [AWS Lambda](/apps/lambda) | Events | `axiom.awsLambdaExtensionVersion` | Lambda invocations, duration, errors, cold starts, and memory usage. |
| [Cloudflare Workers](/apps/cloudflare-workers) | Events | `worker.version`, `worker.id`, `request.asOrganization`, `request.colo` | Edge requests, status codes, response duration, execution time, and popular URLs. |
| [Convex](/apps/convex) | Events | `convex.deployment_name` | Function calls, failure rates, slow queries, and write conflicts. |
| [Documentation observability (Do11y)](https://github.com/axiomhq/do11y#integration-dashboard) | Events | `do11y_version`, `eventType` | Traffic sources, scroll depth, link clicks, and code copies. |
| [Generative AI Overview](/use-cases/llm-observability#access-genai-dashboard) | Events | `attributes.gen_ai.operation.name` | Request duration, token usage, cost, errors, and model performance. |
| [Kubernetes Stats](/send-data/kubernetes) | Metrics | `k8s.pod.cpu.usage`, `k8s.pod.memory.usage` | Kubernetes pod and node resource usage from kubelet stats metrics. |
| [Next.js](/send-data/nextjs) | Events | `@app.next-axiom-version` | Requests, errors, functions, edge activity, and web vitals. |
| [OpenTelemetry Traces](/send-data/opentelemetry) | Events | `duration`, `kind`, `name`, `parent_span_id`, `service.name`, `span_id`, `trace_id` | Services, operations, latency, errors, and trace waterfall navigation. |
| [Tailscale](/apps/tailscale) | Events | `nodeId`, `virtualTraffic`, `physicalTraffic`, `start`, `end` | Tailnet audit logs, network flow traffic, active hosts, and user activity. |

Some apps also provide a dashboard when you install them. The [Vercel](/apps/vercel) app provides **Vercel**, the [Netlify](/apps/netlify) app provides **Netlify**, and the [Cloudflare Logpush](/apps/cloudflare-logpush) app provides **Cloudflare Website Performance**.

To edit an integration dashboard, [fork it](#fork-dashboards).

## Create dashboards

To create a dashboard, choose one of the following:

- [Generate a dashboard](#generate-dashboards-using-ai) using AI based on a natural-language prompt.
- [Create an empty dashboard](#create-empty-dashboards).
- [Fork an existing dashboard](#fork-dashboards). This is how you make a copy of prebuilt integration dashboards that you can’t directly edit.
- [Duplicate an existing dashboard](#duplicate-dashboards). This is how you make a copy of dashboards other than prebuilt integration dashboards.

After creating a dashboard:
- [Add dashboard elements](/dashboard-elements/create). For example, add a table or a time series chart.
- [Configure the dashboard](/dashboards/configure). For example, control who can access the dashboard and change the time range.

## Generate dashboards using AI

Explain in your own words what you want to see in your dashboard and Axiom’s AI generates it in seconds.

1. In the sidebar, click **Dashboards**.
1. In the top right corner, click **New dashboard**.
1. In Type, click **Generate dashboard**.
1. In Dataset, select the dataset from which you want to generate the dashboard.
1. Add a name and a description. Explain in detail what you want to see in your dashboard. The more specific you are, the closer the generated dashboard matches your expectations.
1. Click **Generate dashboard**.
1. Review the preview, and then click **Save dashboard**.

<Info>
You can currently generate dashboards based on a single dataset. After generating the dashboard, you can edit it and add dashboard elements that rely on data from other datasets.

For event datasets, Axiom samples events to understand the data schema. Around 3,000 events in the last 7 days is usually sufficient. For metrics datasets, Axiom uses metrics reported in the last 24 hours.
</Info>

For more flexibility, use an AI coding assistant with the [Build dashboards skill](/console/intelligence/skills/build-dashboards). This approach supports multiple data sources, iterative follow-up prompts, and using screenshots of existing dashboards from other tools as context.

## Create empty dashboards

1. In the sidebar, click **Dashboards**.
1. In the top right corner, click **New dashboard**.
1. In Type, select **Empty dashboard**.
1. Add a name and a description.
1. Optional: Enter a custom **UID** to create a stable link to the dashboard at `/dashboards/uid/<UID>`. If you leave this field blank, Axiom generates a UID automatically.
1. Click **Create dashboard**.

## Fork dashboards

1. In the sidebar, click **Dashboards**.
1. Find the dashboard in the list and right-click it.
1. Click **Fork dashboard**.

## Duplicate dashboards

1. In the sidebar, click **Dashboards**.
1. Find the dashboard in the list and right-click it.
1. Click **Duplicate dashboard**.
1. Optional: Enter a custom **UID** for the duplicated dashboard, or leave it blank to generate one automatically.

## Delete dashboard

1. In the sidebar, click **Dashboards**.
1. Find the dashboard in the list and right-click it.
1. Click **Delete dashboard**.
1. Click **Delete**.
