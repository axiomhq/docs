Axiom MCP Server exposes [tools](https://modelcontextprotocol.io/docs/concepts/tools) and [prompts](https://modelcontextprotocol.io/docs/concepts/prompts) that AI agents can call.

For setup, see [Axiom MCP Server](/console/intelligence/mcp-server).

Every organization-scoped tool accepts an optional `orgId` parameter to override the session’s default organization. Call `listOrganizations` to find available organization IDs.

## Organizations

<ParamField path="listOrganizations" type="Read">
List organizations the current credentials can access. Use an organization’s ID as the optional `orgId` parameter on other tools to override the session’s default organization.

**Example:** “List the Axiom organizations I can access.”
</ParamField>

## Query

<ParamField path="queryDataset" type="Read">
Run an APL query (`apl`) against an events or traces dataset, or pass `queryId` to load the APL or MPL query and time range of a stored query from an Axiom URL’s `qid` parameter. Pass `saveResults: true` to save the query results and return a shareable **Open in Axiom** link. For metrics datasets, use `queryMetrics` instead.

**Example:** “Show the top 10 status codes in `logs` for the last 30 minutes and give me a link to the results.”
</ParamField>

<ParamField path="getSavedQueries" type="Read">
List saved APL queries in your organization.

**Example:** “List my saved queries.”
</ParamField>

## Datasets

<ParamField path="listDatasets" type="Read">
List available Axiom datasets.

**Example:** “List datasets.”
</ParamField>

<ParamField path="getDatasetFields" type="Read">
List fields in an events or traces dataset, including field names and types. For metrics datasets, use `listMetrics` and `listMetricTags` instead.

**Example:** “List the fields in the dataset `logs`.”
</ParamField>

<ParamField path="createDataset" type="Write">
Create a new dataset in the current organization.

**Example:** “Create an events dataset named `app-logs`.”
</ParamField>

<ParamField path="deleteDatasetFields" type="Write">
Queue deletion of fields from an events dataset. The tool asks you to confirm the dataset and the fields before it deletes anything. If your client can’t show the confirmation, or you decline, nothing is deleted. Use exact field names from `getDatasetFields`, up to 50 fields per call. You can queue one deletion per dataset every 5 minutes. The deletion is asynchronous and can take several hours.

The tool can’t delete system fields such as `_time` and `_sysTime`, map fields, or fields in datasets that are metrics datasets, shared, schema-locked, or managed by Axiom such as `axiom-audit`. Deleting fields can’t be undone. For more information, see [Delete fields](/reference/datasets#delete-fields).

**Example:** “Delete the fields `debug_blob` and `tmp_id` from the dataset `logs`.”
</ParamField>

## API tokens

<ParamField path="listTokens" type="Read">
List active API-token metadata. Pass a token ID to inspect its permissions. Token secrets are omitted.

**Example:** “List API tokens with access to `checkout-traces`.”
</ParamField>

<ParamField path="prepareApiToken" type="Read">
Prepare a prefilled API-token creation form in Console. The user creates the token. The tool does not return token secrets.

**Example:** “Prepare an ingest-only token for `checkout-traces` that expires in 30 days.”
</ParamField>

## Metrics

<ParamField path="listMetrics" type="Read">
List available metric names in a dataset.

**Example:** “List metrics in the `metrics` dataset.”
</ParamField>

<ParamField path="listMetricTags" type="Read">
List tags available for filtering metrics in a dataset.

**Example:** “What tags can I filter on in the `metrics` dataset?”
</ParamField>

<ParamField path="getMetricTagValues" type="Read">
Get values for a specific metric tag in a dataset.

**Example:** “List values for the `service.name` tag in `metrics`.”
</ParamField>

<ParamField path="searchMetrics" type="Read">
Search for metrics that match a known tag value.

**Example:** “Find metrics tagged with `service.name` = `api-gateway`.”
</ParamField>

<ParamField path="queryMetrics" type="Read">
Run an MPL query against an Axiom metrics dataset.

**Example:** “Show CPU usage for `api-gateway` over the last hour.”
</ParamField>

<ParamField path="getMetricsSpec" type="Read">
Get the MPL reference for a metrics dataset.

**Example:** “Show the MPL reference for the `metrics` dataset.”
</ParamField>

## Annotations

<ParamField path="getAnnotations" type="Read">
List [annotations](/annotations) in a time range.

**Example:** “Show deployment annotations for `logs` from the last hour.”
</ParamField>

<ParamField path="manageAnnotations" type="Write">
Create, update, or delete an [annotation](/annotations). To create an annotation, pass the datasets whose charts show it and its type, such as `deploy` or `incident`. If you omit the time, the annotation marks the current time. To update or delete an annotation, pass its ID from `getAnnotations`. An update changes only the fields you pass. Deleting an annotation can’t be undone.

**Example:** “Add a `deploy` annotation to `logs` for the checkout release that went out 10 minutes ago.”
</ParamField>

## Dashboards

<ParamField path="listDashboards" type="Read">
List dashboards in your organization.

**Example:** “List my dashboards.”
</ParamField>

<ParamField path="getDashboard" type="Read">
Get details for a dashboard by UID.

**Example:** “Show the configuration for dashboard `abc123`.”
</ParamField>

<ParamField path="createDashboard" type="Write">
Create a dashboard from a JSON document.

**Example:** “Create a dashboard that charts error rate for `logs` over the last 24 hours.”
</ParamField>

<ParamField path="replaceDashboard" type="Write">
Replace the whole document of a dashboard by UID. Use it to add or remove charts, or to change the layout, sections, or dashboard settings.

**Example:** “Add a chart for p99 latency to dashboard `abc123`.”
</ParamField>

<ParamField path="updateDashboardChart" type="Write">
Change a single chart in an existing dashboard by chart ID. Only the fields you change are sent.

**Example:** “Change the time range on chart `chart-1` in dashboard `abc123` to the last 6 hours.”
</ParamField>

<ParamField path="deleteDashboard" type="Write">
Delete a dashboard by UID.

**Example:** “Delete dashboard `abc123`.”
</ParamField>

## Monitors and notifiers

<ParamField path="checkMonitors" type="Read">
Check monitors and their current statuses.

**Example:** “Which monitors are currently alerting?”
</ParamField>

<ParamField path="getMonitor" type="Read">
Get a monitor’s full definition by ID, including the complete query text.

**Example:** “Show the full configuration for monitor `mon_123`.”
</ParamField>

<ParamField path="getMonitorHistory" type="Read">
Get a monitor’s history between `startTime` and `endTime`, newest first. Set `kind` to `notification` (default) to list notifications sent, one row per delivery. Set `kind` to `run` to list every run, one row per run and group, whether or not a notification was sent. Pass one value for `kind`, not both.

For runs, the API returns at most the newest 1,000 runs in the range, and the tool notes when that limit is reached. By default, the tool shows only the newest 100 rows for both kinds. Set `truncate: false` to show all rows received.

**Example:** “Show every run of monitor `mon_123` in the last 24 hours, including errored runs.”
</ParamField>

<ParamField path="listNotifiers" type="Read">
List configured notifiers.

**Example:** “List notifiers.”
</ParamField>

<ParamField path="createMonitor" type="Write">
Create a new monitor.

**Example:** “Create a monitor that alerts when error rate in `logs` exceeds 5%.”
</ParamField>

<ParamField path="updateMonitor" type="Write">
Update an existing monitor by ID.

**Example:** “Update monitor `mon_123` to use a 5-minute threshold window.”
</ParamField>

<ParamField path="deleteMonitor" type="Write">
Delete a monitor by ID.

**Example:** “Delete monitor `mon_123`.”
</ParamField>

<ParamField path="createNotifier" type="Write">
Create an email notifier. For other notifier types such as Slack or webhooks, the tool doesn’t create the notifier. Instead, it gives you a link to the Notifiers page in the Axiom Console where you configure and save the notifier yourself. This keeps credentials such as tokens and webhook URLs out of the conversation with the agent.

**Example:** “Create an email notifier that sends alerts to `oncall@example.com`.”
</ParamField>

<ParamField path="updateNotifier" type="Write">
Update an existing email notifier by ID. For other notifier types, the tool doesn’t update the notifier. Instead, it gives you a link to the notifier in the Axiom Console where you edit and save it yourself.

**Example:** “Update notifier `ntf_123` to send alerts to `oncall@example.com`.”
</ParamField>

<ParamField path="deleteNotifier" type="Write">
Delete a notifier by ID.

**Example:** “Delete notifier `ntf_123`.”
</ParamField>

## Labels

<ParamField path="listLabels" type="Read">
List organization resource labels (`id`, `name`, `description`, `color`), with an optional `name` filter.

**Example:** “List all resource labels in this organization.”
</ParamField>

<ParamField path="manageLabels" type="Write">
Create, update, or delete a label in the organization catalog. Deleting a label removes it from every resource. This tool doesn’t assign labels to resources; use `setLabels` for that.

**Example:** “Create a label named `production` with description `Production resources`.”
</ParamField>

<ParamField path="setLabels" type="Write">
Replace all labels on one dataset, dashboard, monitor, notifier, or integration dashboard. Pass the complete set of label IDs to keep on the resource; omitted IDs are removed, and an empty list clears all labels.

**Example:** “Assign the `production` label to the `logs` dataset.”
</ParamField>

## Service map

These tools are available when service map is enabled for your organization.

<ParamField path="services-getMap" type="Read">
Get the service dependency graph, including call volume, errors, and approximate latency.

**Example:** “Show the service map for the last hour.”
</ParamField>

<ParamField path="services-getChanges" type="Read">
Report what changed in the service dependency graph, such as new or missing dependencies and latency regressions.

**Example:** “What changed in the service map in the last 6 hours?”
</ParamField>

<ParamField path="services-getEdgeHistory" type="Read">
Get time-series history for a service’s dependency edges.

**Example:** “Show edge history from `api-gateway` to `checkout` over the last day.”
</ParamField>

## OpenTelemetry

These OpenTelemetry and GenAI tools are available on [header-based authentication](/console/intelligence/mcp-server#header-based-authentication) connections when `?with-otel=1` is set on the MCP URL. They aren’t exposed on OAuth sessions.

### OpenTelemetry tracing and service metrics

<ParamField path="otel-listServices" type="Read">
List available OpenTelemetry services in a traces dataset.

**Example:** “List OpenTelemetry services in `traces` over the last hour.”
</ParamField>

<ParamField path="otel-listOperations" type="Read">
List available OpenTelemetry operations for a service.

**Example:** “List operations for the `checkout` service in `traces`.”
</ParamField>

<ParamField path="otel-getErrorBreakdown" type="Read">
Break down errors for an OpenTelemetry service or operation.

**Example:** “Show the error breakdown for `checkout` over the last 2 hours.”
</ParamField>

<ParamField path="otel-getServiceMetrics" type="Read">
Get latency percentiles, error rates, and throughput over time for an OpenTelemetry service by operation.

**Example:** “Show service metrics for `api-gateway` over the last hour.”
</ParamField>

<ParamField path="otel-getOperationMetrics" type="Read">
Get detailed latency, error rate, and throughput metrics for a specific service operation.

**Example:** “Show operation metrics for `POST /orders` on `checkout`.”
</ParamField>

<ParamField path="otel-getTraceSpans" type="Read">
Fetch all spans for a trace ID.

**Example:** “Get all spans for trace `4bf92f3577b34da6a3ce929d0e0e4736`.”
</ParamField>

<ParamField path="otel-findTraces" type="Read">
Search for traces matching filters such as service, operation, duration, or error status.

**Example:** “Find slow traces over 2 seconds in `checkout` from the last hour.”
</ParamField>

<ParamField path="otel-findSimilarTraces" type="Read">
Find traces with a similar structure or behavior to a reference trace.

**Example:** “Find traces similar to `4bf92f3577b34da6a3ce929d0e0e4736`.”
</ParamField>

<ParamField path="otel-getTraceCriticalPath" type="Read">
Find the critical path (longest blocking chain) through a trace.

**Example:** “Find the critical path for trace `4bf92f3577b34da6a3ce929d0e0e4736`.”
</ParamField>

<ParamField path="otel-findTraceAnomalies" type="Read">
Detect anomalous traces in a dataset based on latency or error behavior.

**Example:** “Find trace anomalies for `checkout` over the last 6 hours.”
</ParamField>

### GenAI observability

<ParamField path="genai-getOverview" type="Read">
Summarize GenAI request volume, latency, token usage, errors, and estimated cost across models and providers.

**Example:** “Give me a GenAI overview from `traces` for the last 24 hours.”
</ParamField>

<ParamField path="genai-analyzeTokenUsage" type="Read">
Analyze input and output token usage across GenAI models, providers, or capabilities.

**Example:** “Analyze token usage by model in `traces` over the last day.”
</ParamField>

<ParamField path="genai-getModelPerformance" type="Read">
Evaluate latency percentiles, throughput, and error rates for GenAI models.

**Example:** “Show model performance in `traces` over the last 6 hours.”
</ParamField>

<ParamField path="genai-analyzeCosts" type="Read">
Estimate GenAI token costs by model, provider, or capability.

**Example:** “Break down estimated GenAI costs by model for the last 7 days.”
</ParamField>

<ParamField path="genai-findErrors" type="Read">
Find and group errors across GenAI spans.

**Example:** “Find GenAI errors in `traces` from the last hour.”
</ParamField>

<ParamField path="genai-compareModels" type="Read">
Compare latency, token usage, error rates, and cost across GenAI models.

**Example:** “Compare GenAI models used in `traces` over the last 7 days.”
</ParamField>

<ParamField path="genai-analyzeToolUsage" type="Read">
Analyze GenAI tool call frequency, latency, and error rates.

**Example:** “Analyze GenAI tool usage in `traces` over the last 24 hours.”
</ParamField>

<ParamField path="genai-getCapabilityMetrics" type="Read">
Get latency, token usage, cost, and error metrics grouped by `gen_ai.capability.name` and `gen_ai.step.name`.

**Example:** “Show GenAI capability metrics from `traces` for the last 24 hours.”
</ParamField>

**Example:** “Find the docs for creating a threshold monitor.”
</ParamField>

<ParamField path="readAxiomDoc" type="Read">

## Feedback

<ParamField path="sendFeedback" type="Write">
Send feedback to the Axiom team about MCP tool descriptions, results, errors, or missing capabilities.

**Example:** “Report that the `queryDataset` time-range description is unclear.”

</ParamField>

## Prompts

Axiom MCP Server also ships prebuilt prompts for clients that support MCP prompts.

<ParamField path="explore-unknown-dataset" type="Prompt">
Explore an unknown dataset to understand its structure, content, and potential use cases.

**Example:** “Explore the `otel-demo` dataset and summarize what it’s for.”
</ParamField>

<ParamField path="detect-anomalies-in-events" type="Prompt">
Detect anomalies using statistical analysis and pattern recognition across a dataset.

**Example:** “Look for anomalies in `logs` over the last 6 hours.”
</ParamField>

<ParamField path="correlate-events-across-datasets" type="Prompt">
Find patterns and correlations between events across multiple datasets.

**Example:** “Correlate errors in `logs` with deploys in `cicd` for the last day.”
</ParamField>

<ParamField path="data-quality-investigation" type="Prompt">
Investigate data quality issues such as missing data, inconsistencies, and collection problems.

**Example:** “Check `logs` for gaps or schema inconsistencies in the last 24 hours.”
</ParamField>

<ParamField path="establish-performance-baseline" type="Prompt">
Establish performance baselines for a dataset to support monitoring and anomaly detection.

**Example:** “Establish a latency baseline for `api` over the last 7 days.”
</ParamField>

<ParamField path="monitor-health-analysis" type="Prompt">
Analyze monitor health, alert patterns, and effectiveness.

**Example:** “Analyze which monitors flap the most this week.”
</ParamField>

<ParamField path="investigate-service-topology" type="Prompt">
Walk a system’s service dependency graph to find what talks to what, which dependency is at fault, and when it changed. Available when service map is enabled for your organization.

**Example:** “Investigate the topology around `api-gateway`.”
</ParamField>

The following OpenTelemetry prompts are available on [header-based authentication](/console/intelligence/mcp-server#header-based-authentication) connections when `?with-otel=1` is set on the MCP URL:

<ParamField path="investigate-service-outage" type="Prompt">
Follow a systematic workflow to investigate service outages and performance degradation.

**Example:** “Run `investigate-service-outage` for `checkout` in `traces`.”
</ParamField>

<ParamField path="performance-degradation-analysis" type="Prompt">
Analyze service performance issues and identify optimization opportunities against a baseline period.

**Example:** “Run `performance-degradation-analysis` for `api-gateway` in `traces`.”
</ParamField>

<ParamField path="new-service-health-baseline" type="Prompt">
Establish performance baselines and a monitoring strategy for a new service.

**Example:** “Run `new-service-health-baseline` for `billing-api` in `traces`.”
</ParamField>

<ParamField path="trace-analysis-workflow" type="Prompt">
Follow a structured workflow to analyze a distributed trace and identify bottlenecks.

**Example:** “Run `trace-analysis-workflow` for trace `4bf92f3577b34da6a3ce929d0e0e4736`.”
</ParamField>

<ParamField path="distributed-system-health-check" type="Prompt">
Run a health check across all services in a distributed system.

**Example:** “Run `distributed-system-health-check` on `traces` for the last 24 hours.”
</ParamField>

Axiom plans to support MCP [resources](https://modelcontextprotocol.io/docs/concepts/resources) in the future.
